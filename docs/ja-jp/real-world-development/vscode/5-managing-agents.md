GitHub Copilot をエージェントモードにすると、コードベースを調査し、変更を提案し、ファイルを編集して、コマンドを実行します。VS Code の Copilot Chat では、ツールの呼び出しやファイル編集をリアルタイムで確認できます。差分を見ながら変更を個別に保持または取り消し、エディターを離れずに追加のプロンプトを送って作業を調整できます。

この演習では、次の内容を学習します。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして保持します。
- セッションの途中で指示し、ハイコントラストモードにライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中にデザインチームから、既定のテーマが暗すぎると感じるユーザー向けにライトモードも追加したいという要望がありました。新しい会話を始めず、既存のセッションを調整して機能を広げます。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが確認するファイル、実行するコマンド、提案する編集など、各手順が表示されます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにインラインで表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中、チャットをスクロールして各ツール操作を確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. 編集内容が提案されたら、差分を確認します。
   - **Keep** を選択すると変更を保持します。
   - **Undo** を選択すると変更を元に戻し、エージェントに再試行させます。
4. チャット上部の **Files changed** を開き、このセッションでエージェントが変更したファイルをすべて確認することもできます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** を表示します。許可するコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。変更内容を要約する最終メッセージが表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたので、同じ会話を使ってライトモードの切り替えを追加します。会話を続けると、エージェントは以前の作業で変更したコンポーネント、スタイルの方法、Local Storage のパターンを維持できます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送ります。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を確認し、ライトモードの追加を提案します。
3. ハイコントラストのときと同様に新しい編集をレビューし、それぞれ **Keep** または **Undo** を使います。
4. エージェントが望まない方向に進む場合 (たとえば切り替え UI を想定外にリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、明確な追加指示を送ります。

> [!TIP]
> 実行中のセッションを調整すると、最初からやり直すより速く進められます。「CSS を簡潔にして、セレクターを重複させず CSS 変数を使う」「トグルを 3 つにせず、既存の設定パネルにライトモードを統合する」「両方のトグルにキーボードショートカットも追加する」など、追加プロンプトで修正、方向転換、範囲の拡張ができます。

## 作業対象をレビューする

コミットする前に、エージェントが変更した内容をすべて確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更ファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが表示されます。
3. 変更ファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、Local Storage による設定の保持など、カスタムエージェントのアクセシビリティパターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次の[レッスン][next-lesson]で公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで実行中のセッションを監視・調整しました。ファイル編集を確認し、変更を保持または取り消し、コンテキストを失わず追加プロンプトを送って作業を広げました。

このレッスンでは、次の内容を学びました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を保持または取り消す。
- 追加プロンプトで実行中のセッションを調整する。

次の[レッスン][next-lesson]では、アクセシビリティの変更を PR として公開し、このラボでローカルのカスタムエージェントが作成した変更をレビューします。
